# Component development

This repository publishes a shadcn Registry component, not an application. Storybook and tests are
development-only consumers of the real source in `registry/default/calendar/calendar.tsx`. The
published Registry continues to be generated by `shadcn build`.

## Setup and Storybook

Use Node.js 20.19 or newer and install the lockfile exactly:

```bash
npm ci
npm run storybook
```

Storybook runs at `http://localhost:6006` with hot updates, Props Controls, generated docs, and the
test panel. `npm run build-storybook` creates the ignored `storybook-static/` output.

Stories live in `stories/*.stories.tsx` and import the Registry source directly. To add one:

1. Reuse the typed `Meta` and `StoryObj` pattern in `Calendar.stories.tsx`.
2. Use fixed constructor dates, local assets, and fixed content. Do not use `new Date()` without
   arguments, randomness, network images, or current-time assertions.
3. Add a `play` function only for behavior best verified in a browser. All stories already receive
   a render smoke test.
4. If a scenario is not supported by the public API, document the limitation instead of extending
   the component as part of Storybook work.

The Storybook preview loads Tailwind through Vite so the component's utility classes and story
styles render without adding anything to the Registry consumer's dependency list.

## Tests

Run deterministic jsdom behavior tests with:

```bash
npm run test
```

Tests live beside the Registry component and use accessible roles, labels, callbacks, and public
data attributes. When fixing a reproducible bug, first add the smallest regression case that fails
for the reported behavior, then make the focused fix and keep the test.

Run Storybook stories in headless Chromium with:

```bash
npx playwright install chromium
npm run test:browser
```

The browser suite uses Storybook's official Vitest addon. It smoke-tests every Story and runs each
`play` interaction without requiring a separately running Storybook server. It complements unit
tests; it does not prove visual equivalence or eliminate the need for UI review.

## Quality gate and CI

`npm run check` runs TypeScript, ESLint, Prettier, unit tests, and the Registry build. Browser tests
remain separate because they require a downloaded browser and system packages. Pull request CI runs
both jobs, installs dependencies with `npm ci`, installs Chromium for browser tests, and also builds
Storybook.

When CI fails, start with the first failed command and reproduce it locally. Do not skip a test or
weaken a rule to make the pipeline green. Browser failures show the Story name and failed `play`
assertion; use `npm run storybook` to reproduce interactively.

The two build products are independent:

- `npm run build` executes `shadcn build` and validates the distributable Registry JSON.
- `npm run build-storybook` validates the development and documentation site only.

Neither Storybook nor its CSS/testing dependencies are included in the Registry item delivered to
component consumers.
